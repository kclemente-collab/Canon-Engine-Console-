## THE TWO-STAGE RULE

### STAGE 1 — BUFFER (Capture Everything Fast)

```
The Grok buffer is the intake queue.
Treat it as Skill Type A: Raw Capture.

Dump everything here first:
- New character details discovered
- Material properties found
- Render techniques that worked
- Prompt blocks that produced results
- Aesthetic observations
- Story ideas
- World-building fragments
- Anything that gleams

Rules for Stage 1:
✓ Do NOT decide where it goes yet
✓ Do NOT edit or refine it yet
✓ Do NOT wait until it's perfect
✓ Capture now — classify later
✓ Fragments are acceptable
✓ Messy is acceptable
✓ Duplicates are acceptable at intake

What the buffer solves:
→ You don't lose updates
→ You don't have to decide immediately
   where things go
→ You can batch-process later
→ The friction of capture is removed

Buffer = intake queue. Nothing more.
Nothing less. Everything first.
```

---

### STAGE 2 — CANONICALIZE + LOG

```
Run this pass on a schedule:
Daily if generating actively.
Weekly minimum regardless.

The pass takes 30 minutes maximum.
It processes everything in the buffer.

For each item in the buffer,
ask one question:

IS THIS A FACT OR A CHANGE?
```

```
IF IT IS A FACT:
→ Move it to the correct canonical location

Canonical locations in FGE:

CHARACTER LEDGER

→ Any new character introduction
→ Physical description updates
→ Wardrobe additions
→ Scene Law discoveries
→ Morph Pet reveals
→ Card line refinements

CONSTITUTION (ET-CON-000001)

→ Threshold discoveries

SKILL MODULES
→ Prompt blocks that worked
→ Renderer mode discoveries
→ Material translations that produced results
→ Agent instruction improvements

MATERIAL UNIVERSE
→ New materials sourced and tested
→ Prompt refinements for existing materials
→ Character assignments confirmed

STYLE BANK

→ Log it in the Thread Digest
→ Optionally package it in an Upgrade Doc

```

## THE BUFFER PROTOCOL IN PRACTICE

### Daily Flow (when actively generating)

```
DURING SESSION:
Everything that works → dump to buffer
Everything discovered → dump to buffer
Don't stop to classify
Don't stop to organize
Generate and capture

END OF SESSION:
5-minute triage pass:
- Flag anything urgent
  (character canon change,
   constitutional amendment needed)
- Leave rest for weekly pass
```

### Weekly Flow (mandatory)

```
ONCE PER WEEK — 30 minutes max:

Step 1: Open buffer (10 min)
Read everything captured this week.
Don't act yet. Just read.
Note: what is fact, what is change.

Step 2: Process facts (10 min)
Move each fact to canonical home.
One location. No duplicates.
If unsure: Character Ledger
is the safest default.

Step 3: Log changes (5 min)
Thread Digest entry for each change.
Date, what, from, to, why.

Step 4: Clear buffer (5 min)
Anything processed: remove from buffer.
Anything still unclear: flag for next week.
Buffer should approach empty.
An empty buffer = a healthy system.
```

## WHAT THE BUFFER DOES NOT SOLVE

These require the canonicalization pass.
The buffer alone cannot:

```
✗ Update Character Ledger entries
  → Requires: move fact to ledger

✗ Keep modules and templates
  canonical and deduplicated
  → Requires: compare + merge pass

✗ Create reliable change history
  (Thread Digests)
  → Requires: log each change explicitly

✗ Produce clean Upgrade Package documents
  → Requires: package pass after logging
```

The buffer is the inbox.
Canonicalization is the filing system.
Both are required. Neither replaces the other.

## THE CONVERGENCE TEST

At any point, run this test
to measure system health:

```
QUESTION 1:
Is there anything in the buffer
older than one week?
→ Yes: schedule canonicalization pass now
→ No: system is healthy

QUESTION 2:
Does any character have details
in two different places?
→ Yes: deduplication needed
→ No: canonical integrity maintained

QUESTION 3:
Has any render technique produced
good results that aren't yet
in a skill module?
→ Yes: buffer that technique now,
       canonicalize this week
→ No: system is capturing correctly

QUESTION 4:
Is the Constitution the actual
highest authority —
or have working session habits
drifted from it?
→ Drifted: run a constitution review pass
→ Aligned: system is converging

CONVERGENCE STATUS:
All four answers clean = system converging
One answer flagged = maintenance needed
Two+ answers flagged = schedule full pass
```
